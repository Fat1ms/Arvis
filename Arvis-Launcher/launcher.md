1. Установка и Обновление (Core Lifecycle)
Это фундамент лаунчера. Его задача — гарантировать, что у пользователя есть актуальный и работающий код.

Мастер первой установки:

Автоматическая проверка наличия Python (и предложение установить нужную версию, если её нет).

Создание виртуального окружения (venv) — критично, чтобы не засорять систему пользователя.

Установка зависимостей (pip install -r requirements.txt) с отображением прогресс-бара.

Умное обновление (OTA Updates):

Проверка версии Arvis на GitHub (или твоем сервере) при запуске лаунчера.

Кнопка «Обновить» с выбором ветки: Stable (для всех) или Dev/Nightly (для тестеров).

Автоматическое обновление зависимостей после обновления кода (если изменился requirements.txt).

Целостность файлов: Функция «Починить» (Repair), которая перекачивает поврежденные файлы или пересоздает виртуальное окружение.

2. Менеджер Моделей (AI Resource Management)
Самая важная часть для AI-ассистента. Пользователю сложно качать модели вручную, лаунчер должен делать это сам.

Витрина моделей (Model Store):

Список доступных LLM (Llama 3, Mistral, Gemma) и STT/TTS моделей.

Фильтры: «Быстрые (для слабых ПК)» vs «Умные (для мощных ПК)».

Кнопка «Скачать/Удалить» для каждой модели.

Выбор активных моделей: Выпадающие списки, где юзер выбирает, какая модель сейчас отвечает за чат, а какая — за голос.

Интеграция с Ollama (если используется):

Проверка, установлен ли Ollama.

Команда ollama pull прямо из интерфейса лаунчера.

3. Настройки и Конфигурация
Перенос настроек в лаунчер позволяет не трогать конфиг-файлы вручную.

Учетная запись (твой пункт):

Авторизация/Регистрация.

Синхронизация настроек (если планируешь облако).

Локальная защита (PIN-код на запуск, если это приватный ассистент).

Железо и Производительность:

Выбор устройства для инференса: CPU или GPU (CUDA/ROCm).

Настройка потребления ОЗУ (если применимо).

Пути: Выбор папки, где Arvis хранит логи, историю чатов и скачанные модели.

4. Диагностика и Обратная связь
Поможет тебе как разработчику быстрее чинить баги.

Консоль логов: Вкладка в лаунчере, где в реальном времени бегут логи запуска. Если Arvis упадет, пользователь увидит ошибку здесь, а не просто вылет окна.

Баг-репорт (твой пункт):

Форма: Тема, Описание, Вложения (скриншоты).

Галочка «Прикрепить лог-файл» (автоматически собирает latest.log).

Отправка напрямую в GitHub Issues (через API) или тебе на почту/сервер.

5. Социальная часть и UI
Новости / Changelog: Блок на главной странице лаунчера, который подтягивает последние изменения из GitHub Releases (что нового добавили в версии).

Кнопка «ЗАПУСК»: Большая, красивая кнопка, которая запускает основной процесс main.py из виртуального окружения.

Рекомендуемая структура интерфейса (UI Layout)
Представь лаунчер как приложение с боковой панелью (Sidebar).

Главная (Home):

Большая кнопка "Запустить Arvis".

Статус: "Готов к работе" или "Требуется обновление".

Блок новостей проекта.

Модели (Models):

Таблицы с LLM, STT, TTS. Статусы: "Установлено", "Доступно", "Требует обновления".

Настройки (Settings):

Аккаунт.

Выбор путей установки.

Настройки GPU/CPU.

Отладка (Debug):

Просмотр логов.

Кнопка "Переустановить зависимости".

Кнопка "Сообщить о баге".
