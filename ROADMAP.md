Этот документ описывает план развития проекта Arvis с акцентом на **локальную архитектуру**. Продукт будет развиваться от полностью оффлайн-функционального MVP до коммерческого продукта с опциональными серверными возможностями.

## Выбор провайдеров и заметки по лицензиям (важное)

В рамках перехода Arvis на полностью локальную версию и переработки источников данных мы принимаем следующие решения и даём важные лицензионные замечания:

- Выбранные первичные провайдеры (приоритет цена→качество):
    - ✅ **SerpAPI** — основной платный провайдер для web-поиска. Интегрируется как опция, требующая ключ пользователя.
    - ✅ **GNews** — основной провайдер новостей. Интегрируется с поддержкой бесплатного и коммерческого планов.
    - ✅ **Open-Meteo** — основной провайдер погоды (бесплатный, open-source, без ключа). Идеально для локальной версии.

- Запасные/фоллбек варианты:
    - RSS-агрегатор для новостей (офлайн-дружелюбный, бесплатно настраивается под источники).
    - Google Custom Search (Programmable Search) — альтернатива SerpAPI по цене/запросам.
    - DuckDuckGo / scraping — только как fallback; возможны ограничения TOS/нестабильность.

- Заметки по лицензиям и рискам:
    - Heretic: распространяется под AGPL-3.0 — мы НЕ включаем её исходники в репозиторий Arvis и НЕ встраиваем AGPL-код напрямую. Heretic будет опциональным внешним плагином: инструкция по установке и явное согласие пользователя. Это минимизирует риск «заражения» основного кода AGPL-обязательствами, но не заменяет юридическую консультацию для коммерческих дистрибуций.
    - Open-Meteo: код open-source (AGPL), данные под CC BY 4.0 — данные можно использовать с атрибуцией; опция развернуть собственный экземпляр API для полного контроля.
    - OpenWeatherMap / другие коммерческие погодные сервисы: содержат варианты лицензий (CC BY/ODbL/коммерческие), у них есть бизнес-опции, снимающие ShareAlike/атрибуцию за плату — учитывать при коммерческом выпуске.
    - SerpAPI / GNews / NewsAPI: коммерческие сервисы с платными тарифами — важно учесть условия использования в коммерческом продукте (ограничения по перепродажи, SLA, attribution).

- Рекомендации по архитектуре в свете лицензий:
    - Heretic реализовать как внешний модуль/плагин: динамическая загрузка (try/import), явная инструкция по установке `pip install heretic-llm` и предупреждение в UI/документации о лицензии AGPL.
    - Все платные провайдеры подключать через адаптеры: пользователь предоставляет ключи, конфиг указывает приоритет провайдеров, по умолчанию используется бесплатный/офлайн-уровень (RSS/Open-Meteo).
    - Хранить кэш (SQLite) локально, чтобы снизить число внешних вызовов и обеспечить оффлайн-режим.

Эти заметки должны быть отражены в дорожной карте, документации и установочных инструкциях.


## Этап 1: Локальный MVP (1-3 месяца)

**Цель:** Выпустить стабильную, полностью функциональную **локальную** версию Arvis.

**Задачи:**

*   **Клиентская часть (Arvis-Client):**
    *   ✅ Полная стабилизация и тестирование миграции на Qt6.
    *   ✅ Реализация надежного голосового ввода через Vosk.
    *   ✅ Интеграция основного голоса (Bark) и запасного (Silero).
    *   ✅ Создание интуитивного интерфейса для текстового чата.
    *   ✅ Интеграция с Ollama для поддержки локальных моделей.
    *   ✅ Реализация базовых команд: запуск программ, открытие сайтов.
    *   ✅ **Интеграция новых провайдеров:**
        *   ⚙️ **Open-Meteo** для погоды (по умолчанию, без ключа).
        *   ⚙️ **GNews** для новостей (с возможностью ввода API-ключа).
        *   ⚙️ **SerpAPI** для веб-поиска (с возможностью ввода API-ключа).
    *   ✅ Создание базового окна настроек (см. SETTINGS.md) для управления локальными функциями и API-ключами.
    *   ✅ Оставить только один метод озвучки (после полной генерации текста).
    *   ⚙️ Завершить рефакторинг ядра (`CORE_REFRACTORING`).
    *   ✅ Улучшение анимаций и полное соответствие макету UX/UI.
    *   ⚙️ Создать для Арвис личность.
    *   ⚙️ Реализовать режим общения "Live".
    *   ⚙️ Оптимизация производительности и потребления памяти.
    *   ✅ Добавление звуковых эффектов.
    *   ⚙️ Возможность просматривать фото\файлы 

*   **Arvis-Launcher (НОВЫЙ КОМПОНЕНТ):**
    *   ✅ Создание отдельного лаунчера для управления клиентом.
    *   ✅ Управление аутентификацией (логин, гостевой режим с 30мин лимитом).
    *   ✅ Управление моделями: LLM (Ollama), STT (Vosk), TTS (Silero).
    *   ✅ Выбор активных моделей STT/TTS с синхронизацией в клиент.
    *   ✅ Перенос настроек из клиента: пользователь (имя, город), язык (интерфейс, речь).
    *   ✅ Проверка и установка обновлений клиента.
    *   ⚙️ Автоматическое скачивание и установка Ollama.
    *   ⚙️ Миграция данных между версиями.

*   **Очистка проекта:**
    *   🧹 Анализ и удаление неиспользуемых файлов и зависимостей.
    *   🧹 Актуализация `requirements.txt`.
    *   🧹 Удаление временных файлов и ненужных скриптов.

*   **Обнаруженные проблемы:**
    *   На текущий момент критичных ошибок нет. Раздел будет обновляться по мере поступления новых данных.

## Этап 3: Серверная инфраструктура и Premium-функции (6-12 месяцев)

**Цель:** Разработать серверную часть для поддержки облачных функций и монетизации.

**Задачи:**

*   **Серверная часть (Arvis-Server):**
    *   ✅ Разработка базового бэкенда на FastAPI.
    *   ✅ Внедрение системы аккаунтов (JWT, роли, 2FA TOTP).
    *   🔐 **Монетизация и дистрибуция (сайт + оплата + скачивание .exe):**
        *   🟡 MVP-скелет уже реализован в коде (billing + downloads + простые `/web/*` страницы).
        *   ⚙️ Определить продуктовую модель: разовая покупка vs подписка (или гибрид).
        *   ⚙️ **Stripe:**
            *   Настроить продукты/цены в Stripe Dashboard (или закрепить прайсы в конфиге).
            *   Настроить webhook endpoints в проде и секреты.
            *   Обработать продление/отмену подписки (invoice.paid, customer.subscription.updated/deleted) → обновлять доступ.
        *   ⚙️ **LiqPay:**
            *   Подтвердить требования по подпискам (у LiqPay отдельный flow для recurring) и реализовать recurring-платежи.
            *   Протестировать sandbox/боевые статусы и idempotency вебхуков.
        *   ⚙️ **Entitlement (доступ после оплаты):**
            *   Нормализовать правила доступа: lifetime для one-time, периодический доступ для subscription.
            *   Добавить админ-инструменты: вручную выдать/отозвать доступ (для поддержки/рефандов).
        *   ⚙️ **Скачивание .exe через временные ссылки:**
            *   Настроить хранение билдов: локально (server disk) или объектное хранилище (S3/R2) + CDN.
            *   Добавить ротацию/версии билдов: какой файл выдаём по умолчанию, история версий.
            *   Усилить защиту ссылок: одноразовость, TTL, лимиты, логирование, rate-limit.
        *   ⚙️ **Сайт (MVP):**
            *   Привести UI к единому виду (landing + кабинет), тексты/политики.
            *   Восстановление доступа/пароля (если нужно для прод-выхода).
        *   ⚙️ **Юридическое/комплаенс (EU/UA):**
            *   Privacy Policy, Terms of Service, Refund Policy, контакты.
            *   Cookies/analytics (если появятся) + согласия.
        *   ⚙️ **Инфраструктура:**
            *   CI/CD сборки `.exe` (подпись, хэш/SHA256, публикация в хранилище).
            *   Мониторинг ошибок платежей/вебхуков.
    *   🔐 Система управления подписками (Free → Premium).
    *   ⚙️ Эндпоинты для облачных функций:
        *   Сохранение истории диалогов в облаке.
        *   Синхронизация настроек между устройствами.
        *   API для интеграции с внешними сервисами.
    *   🔐 Логирование и аудит действий пользователей (для GDPR).
    *   ⚙️ **Обновления клиента:**
        *   Эндпоинт/механика проверки обновлений (последняя версия, changelog, URL скачивания).
        *   Авто-обновление в клиенте или “скачать новую версию” (минимальный безопасный flow).

*   **Клиентская часть (Arvis-Client):**
    *   🔒 Реализация системы входа и выхода из аккаунта.
    *   🔒 Интеграция с Google API / Microsoft Graph для работы с календарем, почтой.
    *   🔒 Разработка интерфейсов для новых премиум-функций.
