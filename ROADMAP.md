# 🚀 Дорожная карта Arvis: Локальный MVP и будущее развитие

Этот документ описывает план развития проекта Arvis с акцентом на **локальную архитектуру**. Продукт будет развиваться от полностью оффлайн-функционального MVP до коммерческого продукта с опциональными серверными возможностями.

**Статус проекта:** 🟡 В разработке (переход на Qt6, фокус на локальную архитектуру)
**Целевой регион:** Украина, Европа
**Языки:** Русский, Украинский, Английский

---

## Выбор провайдеров и заметки по лицензиям (важное)

В рамках перехода Arvis на полностью локальную версию и переработки источников данных мы принимаем следующие решения и даём важные лицензионные замечания:

- Выбранные первичные провайдеры (приоритет цена→качество):
    - ✅ **SerpAPI** — основной платный провайдер для web-поиска. Интегрируется как опция, требующая ключ пользователя.
    - ✅ **GNews** — основной провайдер новостей. Интегрируется с поддержкой бесплатного и коммерческого планов.
    - ✅ **Open-Meteo** — основной провайдер погоды (бесплатный, open-source, без ключа). Идеально для локальной версии.

- Запасные/фоллбек варианты:
    - RSS-агрегатор для новостей (офлайн-дружелюбный, бесплатно настраивается под источники).
    - Google Custom Search (Programmable Search) — альтернатива SerpAPI по цене/запросам.
    - DuckDuckGo / scraping — только как fallback; возможны ограничения TOS/нестабильность.

- Заметки по лицензиям и рискам:
    - Heretic: распространяется под AGPL-3.0 — мы НЕ включаем её исходники в репозиторий Arvis и НЕ встраиваем AGPL-код напрямую. Heretic будет опциональным внешним плагином: инструкция по установке и явное согласие пользователя. Это минимизирует риск «заражения» основного кода AGPL-обязательствами, но не заменяет юридическую консультацию для коммерческих дистрибуций.
    - Open-Meteo: код open-source (AGPL), данные под CC BY 4.0 — данные можно использовать с атрибуцией; опция развернуть собственный экземпляр API для полного контроля.
    - OpenWeatherMap / другие коммерческие погодные сервисы: содержат варианты лицензий (CC BY/ODbL/коммерческие), у них есть бизнес-опции, снимающие ShareAlike/атрибуцию за плату — учитывать при коммерческом выпуске.
    - SerpAPI / GNews / NewsAPI: коммерческие сервисы с платными тарифами — важно учесть условия использования в коммерческом продукте (ограничения по перепродажи, SLA, attribution).

- Рекомендации по архитектуре в свете лицензий:
    - Heretic реализовать как внешний модуль/плагин: динамическая загрузка (try/import), явная инструкция по установке `pip install heretic-llm` и предупреждение в UI/документации о лицензии AGPL.
    - Все платные провайдеры подключать через адаптеры: пользователь предоставляет ключи, конфиг указывает приоритет провайдеров, по умолчанию используется бесплатный/офлайн-уровень (RSS/Open-Meteo).
    - Хранить кэш (SQLite) локально, чтобы снизить число внешних вызовов и обеспечить оффлайн-режим.

Эти заметки должны быть отражены в дорожной карте, документации и установочных инструкциях.

## Этап 2: Расширенные локальные функции (3-6 месяцев)

**Цель:** Добавить продвинутые функции, работающие локально, и подготовиться к будущей монетизации.

**Задачи:**

*   **Клиентская часть (Arvis-Client):**
    *   ⚙️ **Мультимодальность (Vision)**:
        *   Интеграция LLaVA/BakLLaVA через Ollama для анализа изображений
        *   Поддержка перетаскивания файлов (drag & drop) в чат
        *   Анализ скриншотов и фотографий, файлов
    *   ⚙️ **Улучшенный TTS**:
        *   Интеграция Piper TTS (высококачественные локальные голоса)
        *   Поддержка эмоционального синтеза речи
        *   Клонирование голоса (опционально, через Coqui XTTS)
    *   ⚙️ **RAG (Retrieval-Augmented Generation)**:
        *   Локальная база знаний на основе документов пользователя
        *   Индексация PDF, Word, TXT файлов
        *   Поиск по личным заметкам и документам
    *   ⚙️ **Агентные возможности (AI Agents)**:
        *   Function Calling через Ollama (llama3.1+, mistral-nemo)
        *   Автоматизация задач: создание файлов, работа с буфером
        *   Интеграция с локальными приложениями (VS Code, браузер)
    *   ⚙️ **Локальный код-ассистент**:
        *   Интеграция Qwen2.5-Coder, DeepSeek-Coder через Ollama
        *   Code completion и анализ в реальном времени
        *   Объяснение кода и поиск багов
    *   ⚙️ **Умный контекст**:
        *   Сжатие истории диалогов для экономии контекста
        *   Автоматическое определение темы разговора
        *   Персонализация ответов на основе истории

*   **Новые технологии 2024-2025 для интеграции:**
    *   🆕 **Whisper.cpp** — быстрый локальный STT как альтернатива Vosk
    *   🆕 **Kokoro TTS** — новый качественный движок озвучки (MIT лицензия)
    *   🆕 **Llama 3.2 Vision** — мультимодальные модели от Meta
    *   🆕 **Qwen2.5** — новейшие модели Alibaba (хороши для кода и reasoning)
    *   🆕 **Gemma 2** — улучшенные модели от Google для локального запуска
    *   🆕 **Phi-3** — компактные модели Microsoft для слабого железа
    *   🆕 **MCP (Model Context Protocol)** — стандарт от Anthropic для инструментов AI

## Примечания по технологиям

### Рекомендуемые модели Ollama для разных задач:
| Задача | Модель | RAM | Примечание |
|--------|--------|-----|------------|
| Общение (RU/UA) | `gemma2:9b`, `qwen2.5:7b` | 8GB+ | Хорошее качество на русском |
| Код | `qwen2.5-coder:7b`, `deepseek-coder-v2:16b` | 8-16GB | Отлично для программирования |
| Слабое железо | `phi3:mini`, `gemma2:2b`, `qwen2.5:1.5b` | 4GB | Быстрые ответы, базовое качество |
| Vision | `llava:13b`, `bakllava` | 16GB+ | Анализ изображений |
| Reasoning | `qwen2.5:14b`, `llama3.2:3b` | 16GB+ | Сложные рассуждения |

### Альтернативы ключевым компонентам:
- **STT:** Vosk (текущий) → Whisper.cpp, FasterWhisper
- **TTS:** Silero (текущий) → Piper, Kokoro, Coqui XTTS
- **LLM:** Ollama (текущий) → LM Studio, LocalAI, llama.cpp
